<Info>
Identity verification is only available for merchants on the **SafeHaven** provider. Pulse MFB merchants will receive a `400` error.
</Info>

## Overview

The CAS OTT (One-Time Token) flow verifies the identity of sub-account holders. It's a two-step process:

1. **Initiate Verification** — Submit identity details. An OTP is sent to the account holder.
2. **Validate Verification** — Submit the OTP to complete verification.

## Supported Identity Types

| Type | Description |
|------|-------------|
| `BVN` | Bank Verification Number |
| `NIN` | National Identification Number |
| `vNIN` | Virtual NIN |
| `BVNUSSD` | BVN via USSD |
| `CAC` | Corporate Affairs Commission (businesses) |
| `CREDITCHECK` | Credit check |

## Step 1: Initiate Verification

<CodeGroup>

```bash cURL
curl -X POST 	
 https://api-autoramp.thebuidl.xyz/merchants/api/verify-identity \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "BVN",
    "number": "22222222222"
  }'
```

```javascript JavaScript
const response = await fetch('	
 https://api-autoramp.thebuidl.xyz/merchants/api/verify-identity', {
  method: 'POST',
  headers: {
    'x-api-key': 'YOUR_API_KEY',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    type: 'BVN',
    number: '22222222222',
  }),
});

const data = await response.json();
```

```python Python
import requests

response = requests.post(
    '	
 https://api-autoramp.thebuidl.xyz/merchants/api/verify-identity',
    headers={
        'x-api-key': 'YOUR_API_KEY',
        'Content-Type': 'application/json',
    },
    json={
        'type': 'BVN',
        'number': '22222222222',
    },
)

data = response.json()
```

</CodeGroup>

**Response:**

```json
{
  "identityId": "id_abc123",
  "status": "PENDING"
}
```

Save the `identityId` — you'll need it for Step 2.

<CodeGroup>

## Using Identity During Sub-Account Creation

You can pass identity fields directly when creating a sub-account via `POST /merchants/api/sub-account`. This is useful when you want to create and verify in one flow.

<Warning>
When using `identityType`, you **must** also provide the `otp` that was sent to the account holder's phone. Without the OTP, the sub-account creation will fail.
</Warning>

```json
{
  "phoneNumber": "08012345678",
  "emailAddress": "user@example.com",
  "externalReference": "ref-123456",
  "identityType": "BVN",
  "identityNumber": "22222222222",
  "otp": "123456"
}
```

<Warning>
On SafeHaven, `identityType` is **required** for sub-account creation. On Pulse MFB, identity fields are ignored. See [Provider Limitations](/provider-limitations) for details.
</Warning>

## Pricing

Identity verification is charged per request by SafeHaven. The cost is debited directly from your merchant bank account.

| Identity Type | Charged By | Billed To |
|---------------|------------|-----------|
| BVN | SafeHaven | Your merchant bank account |
| NIN | SafeHaven | Your merchant bank account |
| vNIN | SafeHaven | Your merchant bank account |
| BVNUSSD | SafeHaven | Your merchant bank account |
| CAC | SafeHaven | Your merchant bank account |
| CREDITCHECK | SafeHaven | Your merchant bank account |

<Info>
AutoRamp does not add any additional fees on top of the SafeHaven verification charge. The exact cost per verification is set by SafeHaven — contact SafeHaven or your AutoRamp account manager for current pricing.
</Info>

## Error Handling

**Provider not supported:**

```json
{
  "statusCode": 400,
  "message": "Identity verification is only supported with SafeHaven provider"
}
```

**Invalid OTP:**

```json
{
  "statusCode": 400,
  "message": "Invalid or expired OTP"
}
```

## Best Practices

1. **Store the `identityId`** from Step 1 — it's required for validation.
2. **OTPs expire** — validate promptly after receiving the OTP.
3. **Check your provider** before calling identity endpoints — Pulse MFB merchants get a `400` error.
