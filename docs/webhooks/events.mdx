## Account Events

| Event | Description |
|-------|-------------|
| `account.created` | A bank account or sub-account was created for a merchant |

### Account Created Payload

```json
{
  "event": "account.created",
  "data": {
    "accountNumber": "1234567890",
    "accountName": "John Doe",
    "provider": "pulse_mfb",
    "reference": "ref-abc123",
    "bankCode": "090123"
  },
  "timestamp": "2026-07-13T10:00:00.000Z"
}
```

## Onramp Events

| Event | Description |
|-------|-------------|
| `onramp.initialized` | Onramp transaction created, waiting for payment |
| `onramp.updated` | Onramp status changed (e.g. payment received, processing, completed) |
| `onramp.completed` | Payment received and crypto sent to destination |
| `onramp.failed` | Transaction failed |

## Balance Cache Invalidation

When balance-changing webhooks are received, the system automatically invalidates the cached balance data for the affected merchant. This ensures that subsequent balance checks return fresh data from the provider.

The following webhook events trigger cache invalidation:

| Event | Description |
|-------|-------------|
| `account.credit` | Merchant account credited — invalidates main account cache |
| `account.debit` | Merchant account debited — invalidates main account cache |
| `subaccount.inflow` | Sub-account credited — invalidates merchant and sub-account cache |
| `transfer.completed` | Transfer completed — invalidates merchant balance cache |
| `transfer.failed` | Transfer failed — invalidates merchant balance cache |

This ensures that merchants always see the most up-to-date balance information after transactions.
