# Transactions Oversight API

Backend response shapes for the admin "Transactions Oversight" dashboard: `GET /admin/transactions/summary` and `GET /admin/transactions/analytics`.

Both require Admin auth (`JwtAuthGuard`, `AdminGuard`).

There is no committed OpenAPI schema/example for either route yet (the Swagger decorators on `AdminController` only carry a status + description, no response body schema) — the JSON below was generated by running `AdminService.getTransactionsSummary()` / `getTransactionsAnalytics()` directly against mocked data, so the shape and field names are guaranteed to match the current code, not hand-typed.

## `GET /admin/transactions/summary`

- **Controller:** `admin.controller.ts` → `getTransactionsSummary()`
- **Service:** `admin.service.ts` → `AdminService.getTransactionsSummary()`
- **Query params:** none

### What changed

- **Volume/count is now computed across ALL completed transactions** — onramp, offramp, swap, and OTC — including merchant-initiated ones (`MerchantOnrampTransaction`, `MerchantOfframpTransaction`, `MerchantSwapTransaction`), which were previously excluded entirely.
- **Swap ↔ offramp pairs are no longer double-counted.** When a crypto→fiat swap creates both a `SwapTransaction` and its fiat-leg `OfframpTransaction` (linked via `swapId` at the user level, or by matching `reference` at the merchant level, since `MerchantOfframpTransaction` has no FK), that single real-world transaction is now represented once, under `swap`.
- **`swapCompletedVolume` is NGN-valued, not raw token amount.** A swap's `fromAmount` is denominated in whatever token was sold (e.g. USDC), not Naira. When the swap has a linked offramp, its volume uses the offramp's actual NGN amount. Pure crypto-to-crypto swaps (no linked offramp) have no NGN equivalent — they're still counted in `swapCompletedCount` / `totalCount`, but excluded from every volume figure and from `averageValue`'s denominator.
- **OTC trades (`OtcTransaction`) are now included**, as their own `otc` bucket. OTC rows are standalone (no FK to onramp/offramp/swap) and already NGN-denominated (`amount`/`fiatAmountReceived` is the destination fiat amount from the Flint quote), so no dedup or unit conversion was needed — they're a straight add into the totals.

### Response fields

| Field                    | Type     | Description                                                                                     |
| :------------------------ | :------- | :------------------------------------------------------------------------------------------------ |
| `totalVolume`              | `number` | Sum of NGN value across all **completed** onramp + offramp + swap transactions (user + merchant). |
| `totalCount`               | `number` | Count of all transactions regardless of status (user + merchant, deduped swap/offramp pairs).      |
| `successRate`              | `number` | `round(completedCount / totalCount * 100)`, 0 if no transactions.                                  |
| `averageValue`             | `number` | `round(totalVolume / valuedCompletedCount)` — divides only by completed transactions that had an NGN value (excludes crypto-only swaps). |
| `onrampCompletedVolume`    | `number` | NGN volume of completed onramp transactions.                                                       |
| `onrampCompletedCount`     | `number` | Count of completed onramp transactions.                                                            |
| `offrampCompletedVolume`   | `number` | NGN volume of completed **standalone** offramp transactions (excludes swap-linked ones).           |
| `offrampCompletedCount`    | `number` | Count of completed standalone offramp transactions.                                                |
| `swapCompletedVolume`      | `number` | NGN volume of completed swaps that had a linked offramp (NGN-valued); crypto-only swaps contribute 0. |
| `swapCompletedCount`       | `number` | Count of all completed swaps, including crypto-only ones with no NGN value.                        |
| `otcCompletedVolume`       | `number` | NGN volume of completed OTC trades (`OtcTransaction`, user + merchant not distinguished).           |
| `otcCompletedCount`        | `number` | Count of completed OTC trades.                                                                     |
| `unsuccessfulVolume`       | `number` | NGN volume of all non-`COMPLETED` transactions (`PENDING`, `PROCESSING`, `FAILED`, `CANCELLED`).   |
| `unsuccessfulCount`        | `number` | Count of all non-`COMPLETED` transactions.                                                         |

### Example Response (200 OK)

```json
{
  "totalVolume": 3105000,
  "totalCount": 15,
  "successRate": 67,
  "averageValue": 345000,
  "onrampCompletedVolume": 1370000,
  "onrampCompletedCount": 3,
  "offrampCompletedVolume": 700000,
  "offrampCompletedCount": 3,
  "swapCompletedVolume": 760000,
  "swapCompletedCount": 3,
  "otcCompletedVolume": 275000,
  "otcCompletedCount": 1,
  "unsuccessfulVolume": 270000,
  "unsuccessfulCount": 5
}
```

## `GET /admin/transactions/analytics`

- **Controller:** `admin.controller.ts` → `getTransactionsAnalytics()`
- **Service:** `admin.service.ts` → `AdminService.getTransactionsAnalytics()`
- **Query params:**

| Name     | Type   | Required | Description                                              |
| :------- | :----- | :------- | :--------------------------------------------------------- |
| `period` | `enum` | No       | `daily` \| `weekly` \| `monthly` (default `daily`). Controls both the lookback window (30 days / 12 weeks / 12 months) and date bucket format. |

**Not yet updated with this pass** — this endpoint is unchanged and still has the gaps the summary endpoint used to have:

- Counts only, no volume figures.
- No status filter — every row (`PENDING`/`PROCESSING`/`FAILED`/`CANCELLED`/`COMPLETED`) is counted, not just completed ones.
- Merchant transactions (`MerchantOnrampTransaction`, etc.) and OTC trades (`OtcTransaction`) are not included — the underlying query is a raw SQL `UNION ALL` over `onramp_transactions`, `offramp_transactions`, `swap_transactions` only.

Flag if you want this brought in line with `/summary`.

### Response fields (array, one entry per date bucket)

| Field           | Type     | Description                                  |
| :--------------- | :------- | :---------------------------------------------- |
| `date`            | `string` | Bucket label, format depends on `period` (`YYYY-MM-DD`, ISO week, or `YYYY-MM`). |
| `onrampCount`      | `number` | All onramp transactions in this bucket, any status. |
| `offrampCount`     | `number` | All offramp transactions in this bucket, any status. |
| `swapCount`        | `number` | All swap transactions in this bucket, any status.   |
| `totalCount`       | `number` | Sum of the three counts above.                      |

### Example Response (200 OK)

```json
[
  {
    "date": "2026-07-10",
    "onrampCount": 4,
    "offrampCount": 3,
    "swapCount": 2,
    "totalCount": 9
  },
  {
    "date": "2026-07-11",
    "onrampCount": 2,
    "offrampCount": 1,
    "swapCount": 5,
    "totalCount": 8
  }
]
```
